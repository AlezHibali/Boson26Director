# 2–3 分钟本地演示

## 启动与准备

```powershell
npm ci
npm run doctor
# 首次按 .env.example 新建 .env.local 并填写 BOSON_API_KEY。
pwsh -NoProfile -File scripts/start-local.ps1 -Mode demo
```

脚本只绑定 127.0.0.1:3000；-Mode dev 用于开发，-Port 可改端口。脚本不会覆盖现有 .env.local。无密钥时预检给出提示，手动三维预演仍可运行；预检不调用供应商、不证明额度或模型权限可用。

1. 打开首页，点击“准备演示”。麦克风和本地播放停止，恢复 Mira / Suit / EyeSize 0.55 / 45° / 5.2m 的相同预设。
2. 历史、归档和云端任务保留；该按钮不创建付费任务，也不取消云端任务。revision 与动作 token 会正常增加。
3. 在目标机器检查麦克风与耳机。真实物理设备、回声干扰和主观情绪仍须人工完成，合成麦克风自动化不替代这些步骤。
4. 提前准备 fear / anger 两个 Take，完成后点击“保存本地回放”。归档保留实际视频 SHA-256、大小与保存时间。预生成回放始终带标识；不能把它描述成现场即时生成。

## 演示脚本

| 时间      | 操作                                                   | 观众应看到                                             |
| --------- | ------------------------------------------------------ | ------------------------------------------------------ |
| 0:00–0:25 | 展示固定审讯室与准备演示；介绍三维预演和二维表演的边界 | 相同预设、演员与台词，历史明确标记预生成               |
| 0:25–0:55 | 连接语音：“向右转 45 度并挥手。”再说“镜头靠近一点”     | 实际 GLB 转向、Wave 一次、回 Idle；机位更新            |
| 0:55–1:20 | 设置短台词、fear，Action                               | 新 Take 的真实任务状态；等待时可选择已标识的预生成版本 |
| 1:20–1:55 | 选择来源 Take，“只改为愤怒，其他不变，再来一次”        | Retake 继承来源快照；当前机位修改不污染源输入          |
| 1:55–2:30 | 对照两个历史版本；Cut；可展开冻结输入                  | 只有情绪改变；旧音频停止；回看不改变舞台               |
| 2:30–3:00 | 展示归档、刷新恢复与测试摘要                           | 不依赖供应商长期保留；实际验收与人工待验事项分开       |

新生成可能超过演示时长，等待时展示有标识的历史回放和任务状态。机位、灯光、站位、身体动画属于三维预演；Avatar 接收固定正面人像、台词和情绪，不能承诺复现完整三维镜头。

## 故障演练

| 现象                        | 操作                                                                               |
| --------------------------- | ---------------------------------------------------------------------------------- |
| 麦克风拒绝或设备异常        | 停止语音，修复权限后重连；用按钮继续全部核心操作                                   |
| 网络离线 / Realtime 失效    | 场景和历史保留；联网后重连，不重放旧指令                                           |
| Avatar queued / in_progress | 继续查询；准备演示和 Cut 都不会取消云端生成                                        |
| 提交结果未知                | 核实 Boson 记录，关联已确认 ID；确认未接收后显式解除锁；不重新点击付费生成碰运气   |
| 供应商内容 404 / 过期       | 优先本地归档；已有可靠原文件可按下文恢复；没有原文件则解释不可恢复，不自动生成替代 |
| 本地归档缺失 / 大小错误     | 恢复整个 .data 备份，或重新归档仍可用的供应商内容                                  |
| 生成 failed                 | 调整输入后手动创建新 Take；失败原记录保留                                          |

本次联调遇到 anger 的上游内容 404，已使用第四阶段验收下载的同一原始 MP4 恢复，未重新生成。仅本机保有第四阶段私有证据时可执行：

```powershell
# 先停止应用；脚本校验 checkpoint 的 Take ID、情绪与视频尺寸。
npm run demo:recover-stage4
```

归档位于 .data/media/<takeId>.mp4，与 .data/takes.sqlite 一起备份；备份前停止服务。恢复脚本只读取同一 Take 对应的原始文件，不是任意视频上传入口；私有文件不提交 Git。全新克隆没有这些私有媒体，需要自行生成并归档，或从受控备份恢复。

## 验收命令

```powershell
npx playwright install chromium
npm run verify
npm run test:clean
npm run release:info
# 真实 Chrome/Edge 联调：本地真实服务需运行，另需此前缓存的合成语音和两个已完成 Take。
npm run test:stage5:live
```

verify 包括类型、单元、生产构建、凭证检查、Chromium 全量浏览器测试及三浏览器演示测试。完整演示测试要求本机已安装 Chrome 与 Edge；不会自动安装或修改系统浏览器。默认测试在独立的 3100 端口、空供应商密钥、独立数据库中运行，不使用 3000 端口的个人历史或生成服务。

真实联调最多缓存一次短 TTS；每次使用 Chrome 和 Edge 的真实 Realtime 会话与合成麦克风，不创建 Avatar。原始波形仅在 Git 忽略的 private 目录。耗时样本逐条记录；连接到工具结果的时间包含连接、合成录音前导静音与识别，不能当成纯模型延迟。
